4.1.8：PR #371 测试与 Issue #358 复核 ​

本分支同时修改插件与 server；仅覆盖安装 XPI 不会更新服务端修复。尚未发布正式版。

本轮修复 ​

  • 插件与 server 版本标记为 4.1.8，Zotero manifest 上限放宽到 11.*。这只解除版本拦截，不代表已完成 Zotero 11 实机兼容验收。
  • #367（追加，来自 2643358332 的根因分析）：Zotero 11（Firefox 153）对 XUL 布尔属性按"属性是否存在"判定，而 zotero-plugin-toolkit 会给每个生成的菜单节点写 hidden="false"/disabled="false"/checked="false"/type=""，导致菜单在 Zotero 11 上整体不可见、禁用，且每个子项显示勾选标记。同评论预警的图标问题已实锤（Zotero 10.0.6 + 11.0 实测）：Firefox 153 的菜单图标改为从 --menuitem-icon CSS 变量渲染，toolkit 只设旧的 list-style-image（macOS 还跳过 *-iconic class）。现在注册后统一做兼容修补（patchMenuCompat）：清理布尔残留属性与空 type + 主菜单补 menu-iconic class + 设 --menuitem-icon 与 list-style-image（子项不带图标，避免 16px 下误读为勾选）；旧版本语义下均为无操作。注意：不可使用 Zotero 11 zotero-custom-menu-item class —— menuManager.js 会把不在其注册表内的该 class 元素整个移除（[382-389行]），曾导致整个菜单消失，已回滚。Node 测试 13 项。hidden 修复与勾选标记清理已在 Zotero 11.0 实测；图标渲染（主菜单 logo）待复验。
  • 保留 #367 的多主窗口菜单修复。
  • #366：统一加载依赖时补充 bitstring>=4.3.0,<5，覆盖 uv/conda、新安装、显式更新和旧自定义配置；原有自定义配置文件不被此函数覆盖。与用户显式约束冲突时由解析器报错，不静默覆盖用户约束。已有环境检查仅额外强制 bitstring 的兼容区间，继续允许旧引擎版本。skip_install 仍遵循原先不修改环境的约定。
  • #368：插件接收 .pdf/.PDF/.PdF；两种引擎按最后一个扩展名派生输出，保留 a.pdf.pdf 中间的 .pdf；裁剪原文件时不会改写目录名中的 .pdf。旧引擎不再把不存在的产物路径当成成功结果返回。
  • DeepSeek Flash 识别与思考参数没有修改，等待上游支持。另补用户输入防线：LLM API 编辑器保存时，deepseek 服务下手输非 deepseek-v4- 前缀的模型名（如 deepseek-flash）会弹出兼容警告（此类写法不会应用思考控制，可能产生额外费用），可一键自动改为 deepseek-v4-flash。

拉取与本地测试 ​

已有分支：git fetch origin，git switch fix/issue-367-window-menus，git pull --ff-only。

插件在 plugin/ 执行 npm ci、npm test、npm run build，安装 build/zotero-pdf-2-zh.xpi 并重启 Zotero。

服务端先停止原 server，再使用此分支的 server/ 源码与自己的现有配置启动。已有托管环境可在 server 目录执行 python update_packages.py --engine all 后重启；该命令会在现有环境安装/更新依赖。自定义冲突 pin（如 bitstring==5）需移除冲突后再更新。

系统 Python、独立 Windows EXE、外部 Docker 翻译引擎不受托管环境修复覆盖。系统 Python 用户应在实际运行引擎的解释器环境安装 bitstring>=4.3.0,<5；不能只在运行 Flask server 的另一个环境中安装。EXE/外部容器需更新其自身运行时。

实机验收：

  1. Zotero 11 安装、设置页、单/双主窗口菜单、关闭两个窗口的不同顺序、插件禁用/重新启用。
  2. 用 Paper.PDF、Paper.PdF、a.pdf.pdf 测试两个引擎的翻译与附件导入；测试位于 folder.pdf 目录下的原 PDF 裁剪。
  3. 旧引擎输入路径包含 pdf2zh_next，确认不会选错环境。
  4. 三页测试文件跳过 1 页正常；跳过 3 页或更多有明确错误。
  5. 比较/裁剪正常输出；损坏文件或不可写目标不再显示成功。
  6. Windows 普通控制台与重定向日志启动分别确认进度/提示。

已完成的验证及边界 ​

  • Python unittest 26 项通过；包含 PyMuPDF 合成三页文档真实合并、失败后的文档关闭。
  • 插件 Node 测试 10 项通过；TypeScript 检查与 beta XPI 构建通过。
  • 本地 bitstring 4.4.0 的 BitStream 导入与基本解析通过。
  • 依赖修复/命令路由测试使用模拟环境；未完整安装两套翻译引擎、未访问付费模型，也未跑真实 Zotero 11、Windows、conda 或 Docker 验收。
